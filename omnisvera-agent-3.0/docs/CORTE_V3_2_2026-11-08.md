# Corte V3.2 — 2026-11-08

Second cut on top of the battle/city cut. Rule kept: the backend decides, the client only sends intents.

## 1. main.gd split into controllers
`scripts/main.gd` went from ~1610 to ~1200 lines. The parts moved out live in `scripts/controllers/`:

| Controller | Owns |
|---|---|
| `battle_controller.gd` | battle overlay, AI, encounter watch, attack/encounter/ability dialogs, initiative, `arena-*` / `battle-*` / `encounter-*` keys |
| `town_controller.gd` | city screen, merchant, travel to the city, art variant (`user://companion_v3.cfg` → `[town] variant`) |
| `hud_controller.gd` | Diablo orbs, controlled character sheet, purse |
| `connection_keeper.gd` | lost-connection banner, retry backoff 3/5/10/15/30 s, resends the pending intent with the same `request_id` |

Every controller exposes `setup(main)`, `handles(key)`, `received(key, data)`, `failed(key, message, code) -> bool` and `clear()`. `main` dispatches to the first controller whose `handles()` returns true.

Still in `main.gd`: exploration, sessions and preparation.

## 2. Abilities in the arena
- The action list comes from `GET /characters/{id}/action-manifest`, a new read-only route for the owner or the GM.
- The attack list is built from the manifest's `character_attack` entries. If there is no manifest, it falls back to the sheet attacks and the Guard button.
- **Single-target ability:** pick the ability, choose the target, then "Lançar".
- **Multi-target ability:** the client reads the contract from `/gm/actions/describe?ref=`, enters targeting mode and sends `dorn_spell_cast`.
- If the server answers asking for a target, the client switches into targeting mode on its own.
- Summons with a caster on the heroes' side join the hero line.

## 3. Reconnection
- Network errors are 0, 502, 503 and 504. On one of these the game keeps the last state it had and keeps the pending intent instead of discarding it.
- When a poll succeeds again, the client refreshes characters and maps, then resends the intent exactly once. The server deduplicates it by `request_id`.
- The retry button is now labelled "Reenviar".

## 4. Hostile / ally and initiative
- `PATCH /gm/workspace/tokens/{id}/disposition` takes `hostile`, `neutral`, `ally` or `null` (null = automatic).
- In the monster pin, the GM gets four buttons: Hostil / Neutro / Aliado / Automático.
- Neutral and ally tokens never trigger an encounter. Allies fight on the heroes' side.
- Initiative mode is set in the encounter panel:
  - `d20` (default): the server rolls 1d20 per participant through `/rolls`, visible to the table.
  - `manual`: the GM types the numbers, with a "Rolar d20 para todos" button.
  - `fixed`: the order shown is used as is.

## 5. Mobile loading
- `tools/serve_preview.py` serves static files with gzip (cached), ETag and `Cache-Control: no-cache`. An unchanged file gets a 304, so a second visit does not download the .pck/.wasm again.
- `index.html` has a gothic loading screen with an MB counter.
- HTTP timeouts: GET 6 s, commands 12 s.

## 6. Original art, switchable
- `assets/original/` holds city, armorer, potions and guild. They were generated with Flux (`flux-2-klein-9b`) from text-only prompts, with no reference images. `provenance.json` records the model, the prompts and the date. `tools/generate_original_art.py` regenerates them.
- `assets/city/nimalis.json` defines two variants:
  - `original`: the new art, polygon hotspots and gothic merchant frames. This is the default.
  - `rom2`: the Rage of Mages art, mask hotspots and ROM2 frames.
- The **Arte:** button in the city switches between them, and the choice is remembered per device.
- To swap art: replace the image, then adjust `polygon` in the json. Coordinates are in pixels of the image (`art_size`).
